# 关节控制与 PID

> 本文是 grasp_grape 的理论笔记之一。理论部分是通用的；每一节末尾的「在本项目里」
> 给出它在这套代码里的落点和实测数字。

---

## 1. 一个关节要解决的问题

给定期望角度 `q_d(t)`，让实际角度 `q(t)` 跟上它。看起来简单，难点在于关节不是一个
孤立的转动惯量——它挂着后面整条链，链的姿态一变，它感受到的惯量和重力力矩就跟着变。

单关节的动力学可以写成

```
τ = M(q) q̈ + C(q, q̇) q̇ + g(q) + τ_f
```

| 项 | 含义 | 随姿态变化？ |
|---|---|---|
| `M(q) q̈` | 惯性项 | 是。手臂伸直时肩关节感受到的惯量可以是收拢时的好几倍 |
| `C(q, q̇) q̇` | 科氏力与离心力 | 是，且随速度平方增长 |
| `g(q)` | 重力项 | 是。这是**稳态误差的主要来源** |
| `τ_f` | 摩擦 | 近似常量 + 与速度相关的部分 |

关键认识：**这是一个参数随工作点变化的非线性系统**。一组在某个姿态下调好的 PID
增益，换个姿态就不一定合适。

---

## 2. PID 的三项分别在干什么

```
τ = Kp·e + Ki·∫e dt + Kd·ė        其中 e = q_d − q
```

**比例项 Kp** —— 提供恢复力，像一根弹簧。它决定刚度：外部扰动 `τ_ext` 造成的稳态
偏移是 `τ_ext / Kp`。

> 这个式子直接给出了增益的量级。本项目的 CR10，肩部关节承受的重力力矩约 140 N·m
> （臂下方约 24 kg，质心外伸约 0.6 m）。若希望重力造成的下垂不超过 0.02 rad，
> 则 `Kp ≥ 140 / 0.02 = 7000`。这不是试出来的，是算出来的。

**积分项 Ki** —— 消除稳态误差。纯比例控制在恒定负载（重力）下必然留下
`τ_load / Kp` 的偏差，因为没有误差就没有力。积分项把这个偏差随时间累积成力矩，
最终把误差压到零。

代价是**积分饱和（windup）**：若因为某种原因长时间无法到位（比如被卡住），积分项
会累积到极大值，等障碍移开时造成剧烈过冲。工程上用 `i_clamp` 限幅。

**微分项 Kd** —— 提供阻尼，抑制振荡。近似临界阻尼的经验式是

```
Kd ≈ 2·√(Kp · J_eff)
```

`J_eff` 是该关节感受到的等效惯量。

> **本项目踩过的坑**：第一次配增益时给了 `Kp=8000, Kd=500`。按上式，
> `J_eff ≈ 1 kg·m²` 时临界阻尼约 `2√(8000×1) ≈ 180`，500 远在其上。
> 结果不是"更稳"而是发散——在 1 kHz 的控制周期上，过大的微分项把位置量化噪声
> 放大成了自激振荡。**微分项不是越大越稳。**

## 3. 位置接口、力矩接口，和"假的控制"

ROS 的 `ros_control` 里，一个关节可以通过不同的硬件接口驱动：

| 接口 | 控制器写什么 | 仿真里发生什么 |
|---|---|---|
| `PositionJointInterface` | 目标角度 | 若无 PID 增益，`gazebo_ros_control` 退化为 `Joint::SetPosition()`：**直接把角度写进物理引擎** |
| `EffortJointInterface` | 关节力矩 | 物理引擎按力矩积分，关节真实运动 |

`SetPosition` 是一件危险的方便事。它让机器人"看起来"工作得很完美：

- 跟踪误差**恒为零**，因为角度是被写进去的，不是被控出来的
- 关节等效于**无限刚性**：任何接触都变成刚性冲击，能量一步全部反弹
- **力控、接触载荷、跟踪精度全部不可评估**——这些量在这个模型里根本不存在

> **在本项目里**：主线长期使用 `SetPosition`，代价在多处显形——
> 机械臂蹭到藤架能把 132 kg 的整车弹开 0.79 m；果串被 link_attacher 固连到法兰后
> 把关节拽偏约 0.07 rad，而"没有任何东西在调节它"，只能把目标容差从 0.05 放宽到
> 0.12 rad 来回避；而这个放宽后来又让激光对不准果梗，绕了一大圈才发现根子在这里。
>
> 切换到力矩控制后，末端到达指令笛卡尔位姿的误差是 **17 mm**——这是这个项目
> 第一个**有物理意义**的跟踪误差数字。之前那个"2.9 mm"是刚性关节的假象。

## 4. 重力补偿：比调 PID 更有效的一步

既然重力项 `g(q)` 是稳态误差的主要来源，而它可以从模型**算出来**，那就不必让积分项
去慢慢消化它：

```
τ = Kp·e + Ki·∫e dt + Kd·ė + ĝ(q)      ← 前馈
```

`ĝ(q)` 由 URDF 的质量和质心信息通过递归牛顿-欧拉法直接求得。加上它之后：

- 稳态误差主要只剩摩擦，积分项的负担大幅下降
- 可以用**小得多的 Kp**，关节因此更柔顺，接触更安全
- 这是协作机械臂"手一推就能拖动"的基础

更进一步是**计算力矩控制**（computed torque / 逆动力学控制），把整个 `M(q)q̈ + C + g`
都前馈掉，反馈只负责消除模型误差。

---

## 5. 整定方法

**先算，再调。** 从 `Kp = τ_gravity / e_allowed` 起步，`Kd = 2√(Kp·J)`，`Ki` 先给 0。

然后逐关节，**从基座往末端**：

1. 只开 Kp，逐步加大到刚出现振荡，退回 60–70%
2. 加 Kd 到振荡消失（记住上界，见第 2 节）
3. 加 Ki 消除稳态误差，配 `i_clamp` 防饱和
4. 换若干个工作姿态复测——非线性系统在一个姿态调好不代表全局

> **本项目的实测经验**：全局同比例缩放增益是错的。实测每个关节的稳态误差后发现：
> `joint1 0.0002 / joint2 0.0021 / joint3 0.028 / joint5 0.016` 都已可接受，
> 而 `joint4 +0.068`、`joint6 +0.104`（末端 125 mm）是系统性偏差——手腕两个关节
> 要托住激光头和料兜（约 1.7 kg 悬在法兰外 0.24 m），而它们的增益恰恰是六个里最小的。
>
> 但把手腕增益调高（joint4 ×2.7、joint6 ×5）**反而更差**：最大误差从 0.10 涨到
> 0.30 rad，且 8 秒内不再稳定。**远端连杆惯量小，加大 Kp 会把固有频率推到 1 kHz
> 控制环撑不住的地方。**
>
> 而"5 倍增益变化几乎没改变系统性偏差"这一点本身就说明：它可能根本不是增益问题。
> **后来查清了，确实不是。** 见下一节。

## 5b. 三个不是增益的根因（实测记录）

手腕 0.10 rad 的残差、以及力矩控制下手臂根本跑不完一个采摘周期，最后查出三个原因，
**没有一个能靠调增益解决**。这一节把测量过程完整写下来，因为"怎么定位"比"结论"更有用。

### （一）积分饱和：限幅夹的是输出，不是累加器

保持 stow 姿态，同时读稳态误差和实际力矩：

| 关节 | 稳态误差 (rad) | 实际力矩 (N·m) | `Kp·e` | `i_clamp` | `Kp·e + i_clamp` |
|---|---|---|---|---|---|
| joint3 | −0.066 | −31.1 | −330 | 300 | **−30** |
| joint4 | −0.058 | +4.4 | −145 | 150 | **+5** |
| joint6 | −0.090 | −0.9 | −81 | 80 | **−1** |

每一行都满足 `Kp·e + i_clamp = 实际力矩`，误差不到 1 N·m。三行同时吻合不是巧合——
**积分项被顶在限幅值上**，关节就停在"比例项 + 限幅积分 = 负载力矩"的那个偏移上。

关键的一步是接着做的：**让手臂静止 30 秒，看误差走向。**

```
t(s)     joint3    joint4    joint6
 0      -0.0247   -0.0143   -0.0215
10      -0.0096   -0.0045   -0.0065     <- 打开 antiwindup 之后
29      -0.0014   -0.0006   -0.0005
```

而在打开之前，joint3 会自己退回 0，**joint4 和 joint6 三十秒内四位小数纹丝不动**。

原因是 `control_toolbox` 在 `antiwindup` 关闭时，只把积分项的**输出**夹在
`±i_clamp`，底下的误差累加器仍在无限增长。一旦累加器冲过限幅值很远，即使误差反号，
也要花同样长的时间才能退回限幅以内——在那之前积分项就是一个常数。joint3 绕得少所以
能退回来，joint4/joint6 绕得多，就永远卡住。

> **教训**：`i_clamp` 不是抗饱和。抗饱和要夹的是累加器（`antiwindup: true`）。
> 只夹输出的限幅，遇到大范围运动就会退化成"一个走不掉的常数偏置"，
> 而且它伪装成稳态误差，看起来非常像增益不够。

限幅值也一并按**实测保持力矩**重设（joint3 实测 31 N·m 却给了 300，手腕实测约
1 N·m 却给了 80），而不是拍脑袋的整数。

### （二）URDF 缺电机转子的折算惯量：手腕奇异点上直接发散

把误差按时间画出来，问题的性质立刻变了：

```
t(s)  | j4 误差  j4 期望速度  j4 实际速度  j4 力矩 | j6 误差  j6 实际速度  j6 力矩
 0.98 | -0.014     -0.353      -0.298       3.6  | -0.025    -0.298      -3.3
 1.12 |  0.020     -0.353     +11.948     500.0  | -0.060   -44.465    -500.0
 2.94 |  0.529     -0.353     +31.998     500.0  |  0.439   -67.451    -500.0
```

t=1.12 s 突然发散，两个关节的力矩同时钉死在 ±500 N·m 上限。注意位置误差只涨了
0.5 rad，而报出来的速度是 32 rad/s——1.8 秒该走 57 rad。所以那不是运动，是**颤振**，
速度采样在正负之间跳。

**方向相反是关键线索。** joint4 和 joint6 是手腕的两个滚转轴，joint5 过零时两轴共线，
它们之间的**差动模态失去惯量**。惯量趋零时任何增益都嫌高，离散控制环两三个采样就发散。

真机为什么不会？因为减速器。几何减速比 `n` 会把电机转子惯量按 `n²` 折算到输出端：
一个 5e-5 kg·m² 的转子配 100:1 谐波减速器，在关节输出端呈现 **0.5 kg·m²**。
而从 CAD 导出的 URDF 只有连杆的质量属性，**完全没有传动链**：

| 连杆 | 质量 (kg) | ixx (kg·m²) |
|---|---|---|
| Link4 | 1.17 | 0.0029 |
| Link5 | 1.22 | 0.0034 |
| Link6 | **0.205** | **0.00011** |

差了三个数量级。所以这不是"增益调不好"，是**模型里缺了让真机可控的那部分惯量**。

修法（`urdf/cr10_grape.xacro`）：

- Link4/5/6 的惯量对角线下限设为 0.060 / 0.050 / 0.020 kg·m²，作为折算转子惯量
- 手腕关节阻尼 5 → 15 N·m·s/rad（谐波减速器在输出端有真实黏性损耗）
- 六个关节都加 `implicitSpringDamper`——ODE 默认**显式**积分 `<dynamics damping>`，
  阻尼调高本身就会发散；隐式形式把它并进约束求解器

结果：整段运动的跟踪误差 **0.53 rad → 0.003 rad**，实际速度与期望速度小数点后三位一致，
力矩只有 2–3 N·m。

> 这条经验可以推广：**只要在仿真里做力矩控制，就要检查 URDF 有没有折算转子惯量。**
> 没有的话，末端几个轻连杆几乎必然在某个姿态上失稳，而且症状会伪装成"增益整定问题"。

### （三）容差要从整周期测，不能从台架动作测

台架上单条点到点轨迹跟到 0.003 rad，我据此把容差收到 `goal 0.02 / path 0.20`。
跑完整一垄立刻暴露：

```
PATH_TOLERANCE_VIOLATED   joint3  0.200, 0.229     (限值 0.20)
PATH_TOLERANCE_VIOLATED   joint6  0.216
GOAL_TOLERANCE_VIOLATED   joint4  0.054            (限值 0.02)
GOAL_TOLERANCE_VIOLATED   joint1  0.002
GOAL_TOLERANCE_VIOLATED   joint3  0.008
```

最后两行值得注意：**0.002 rad 对 0.02 rad 的限值，根本不是位置超差。**
`joint_trajectory_controller` 打印的是位置误差，但它同时检查
`stopped_velocity_tolerance`——那两次是"到位了但还没停稳"。

真实周期比台架动作难得多：有笛卡尔段、末端挂着果串、上一次 `stop()` 的余速还没泄掉就
下发了新目标。所以最终值取自整垄实测：`path 0.35 / goal 0.05 / goal_time 5 s`，
并把积分增益翻倍（有了 antiwindup 之后这才是安全的），把"到位但还在漂"的收敛时间常数
砍掉一半。

## 6. 容差为什么必须跟着控制方式一起改

`joint_trajectory_controller` 有三个容差，它们的含义**依赖于关节是怎么被驱动的**：

| 容差 | 含义 | 运动学关节 | 力矩关节 |
|---|---|---|---|
| `trajectory` | 路径跟踪偏差上限 | 无意义（永远为零），只能关掉 | 有意义，但要放宽——力矩驱动的关节按设计就会滞后 |
| `goal` | 终点偏差上限 | 可以很紧，但带载偏置会破坏它 | 反映真实定位精度 |
| `stopped_velocity_tolerance` | 终点速度上限 | 无意义，`SetPosition` 的速度不干净收敛 | 有意义，手臂确实会减速 |

> **在本项目里**：运动学版本把 `trajectory` 和 `stopped_velocity_tolerance` 都设为 0
> （关闭），`goal` 放到 0.05 rad。切到力矩控制时这三个都必须重设——把为刚性关节
> 打的补丁带到力矩控制里，会得到一堆互相矛盾的行为。

---

## 7. 延伸：阻抗控制

位置控制的目标是"不管外界如何，都要到达这个位置"，本质上是**刚性**的。当末端要与
环境接触时（本项目的接料围栏会碰到果串），我们更想要的是规定**接触时的力学行为**：

```
F = M_d·(ẍ_d − ẍ) + B_d·(ẋ_d − ẋ) + K_d·(x_d − x)
```

即让末端表现得像一个质量-弹簧-阻尼系统，`K_d` 小就"软"，大就"硬"。这就是阻抗控制。
它的前提是**能够精确控制关节力矩**——所以第 3 节的接口选择不是细节，而是能不能做
接触任务的分水岭。
