# 关节控制与 PID

> 本文是 grasp_grape 的理论笔记之一。理论部分是通用的；每一节末尾的「在本项目里」
> 给出它在这套代码里的落点和实测数字。

---

## 1. 一个关节要解决的问题

给定期望角度 `q_d(t)`，让实际角度 `q(t)` 跟上它。看起来简单，难点在于关节不是一个
孤立的转动惯量——它挂着后面整条链，链的姿态一变，它感受到的惯量和重力力矩就跟着变。

单关节的动力学可以写成

```
τ = M(q) q̈ + C(q, q̇) q̇ + g(q) + τ_f
```

| 项 | 含义 | 随姿态变化？ |
|---|---|---|
| `M(q) q̈` | 惯性项 | 是。手臂伸直时肩关节感受到的惯量可以是收拢时的好几倍 |
| `C(q, q̇) q̇` | 科氏力与离心力 | 是，且随速度平方增长 |
| `g(q)` | 重力项 | 是。这是**稳态误差的主要来源** |
| `τ_f` | 摩擦 | 近似常量 + 与速度相关的部分 |

关键认识：**这是一个参数随工作点变化的非线性系统**。一组在某个姿态下调好的 PID
增益，换个姿态就不一定合适。

---

## 2. PID 的三项分别在干什么

```
τ = Kp·e + Ki·∫e dt + Kd·ė        其中 e = q_d − q
```

**比例项 Kp** —— 提供恢复力，像一根弹簧。它决定刚度：外部扰动 `τ_ext` 造成的稳态
偏移是 `τ_ext / Kp`。

> 这个式子直接给出了增益的量级。本项目的 CR10，肩部关节承受的重力力矩约 140 N·m
> （臂下方约 24 kg，质心外伸约 0.6 m）。若希望重力造成的下垂不超过 0.02 rad，
> 则 `Kp ≥ 140 / 0.02 = 7000`。这不是试出来的，是算出来的。

**积分项 Ki** —— 消除稳态误差。纯比例控制在恒定负载（重力）下必然留下
`τ_load / Kp` 的偏差，因为没有误差就没有力。积分项把这个偏差随时间累积成力矩，
最终把误差压到零。

代价是**积分饱和（windup）**：若因为某种原因长时间无法到位（比如被卡住），积分项
会累积到极大值，等障碍移开时造成剧烈过冲。工程上用 `i_clamp` 限幅。

**微分项 Kd** —— 提供阻尼，抑制振荡。近似临界阻尼的经验式是

```
Kd ≈ 2·√(Kp · J_eff)
```

`J_eff` 是该关节感受到的等效惯量。

> **本项目踩过的坑**：第一次配增益时给了 `Kp=8000, Kd=500`。按上式，
> `J_eff ≈ 1 kg·m²` 时临界阻尼约 `2√(8000×1) ≈ 180`，500 远在其上。
> 结果不是"更稳"而是发散——在 1 kHz 的控制周期上，过大的微分项把位置量化噪声
> 放大成了自激振荡。**微分项不是越大越稳。**

## 3. 位置接口、力矩接口，和"假的控制"

ROS 的 `ros_control` 里，一个关节可以通过不同的硬件接口驱动：

| 接口 | 控制器写什么 | 仿真里发生什么 |
|---|---|---|
| `PositionJointInterface` | 目标角度 | 若无 PID 增益，`gazebo_ros_control` 退化为 `Joint::SetPosition()`：**直接把角度写进物理引擎** |
| `EffortJointInterface` | 关节力矩 | 物理引擎按力矩积分，关节真实运动 |

`SetPosition` 是一件危险的方便事。它让机器人"看起来"工作得很完美：

- 跟踪误差**恒为零**，因为角度是被写进去的，不是被控出来的
- 关节等效于**无限刚性**：任何接触都变成刚性冲击，能量一步全部反弹
- **力控、接触载荷、跟踪精度全部不可评估**——这些量在这个模型里根本不存在

> **在本项目里**：主线长期使用 `SetPosition`，代价在多处显形——
> 机械臂蹭到藤架能把 132 kg 的整车弹开 0.79 m；果串被 link_attacher 固连到法兰后
> 把关节拽偏约 0.07 rad，而"没有任何东西在调节它"，只能把目标容差从 0.05 放宽到
> 0.12 rad 来回避；而这个放宽后来又让激光对不准果梗，绕了一大圈才发现根子在这里。
>
> 切换到力矩控制后，末端到达指令笛卡尔位姿的误差是 **17 mm**——这是这个项目
> 第一个**有物理意义**的跟踪误差数字。之前那个"2.9 mm"是刚性关节的假象。

## 4. 重力补偿：比调 PID 更有效的一步

既然重力项 `g(q)` 是稳态误差的主要来源，而它可以从模型**算出来**，那就不必让积分项
去慢慢消化它：

```
τ = Kp·e + Ki·∫e dt + Kd·ė + ĝ(q)      ← 前馈
```

`ĝ(q)` 由 URDF 的质量和质心信息通过递归牛顿-欧拉法直接求得。加上它之后：

- 稳态误差主要只剩摩擦，积分项的负担大幅下降
- 可以用**小得多的 Kp**，关节因此更柔顺，接触更安全
- 这是协作机械臂"手一推就能拖动"的基础

更进一步是**计算力矩控制**（computed torque / 逆动力学控制），把整个 `M(q)q̈ + C + g`
都前馈掉，反馈只负责消除模型误差。

---

## 5. 整定方法

**先算，再调。** 从 `Kp = τ_gravity / e_allowed` 起步，`Kd = 2√(Kp·J)`，`Ki` 先给 0。

然后逐关节，**从基座往末端**：

1. 只开 Kp，逐步加大到刚出现振荡，退回 60–70%
2. 加 Kd 到振荡消失（记住上界，见第 2 节）
3. 加 Ki 消除稳态误差，配 `i_clamp` 防饱和
4. 换若干个工作姿态复测——非线性系统在一个姿态调好不代表全局

> **本项目的实测经验**：全局同比例缩放增益是错的。实测每个关节的稳态误差后发现：
> `joint1 0.0002 / joint2 0.0021 / joint3 0.028 / joint5 0.016` 都已可接受，
> 而 `joint4 +0.068`、`joint6 +0.104`（末端 125 mm）是系统性偏差——手腕两个关节
> 要托住激光头和料兜（约 1.7 kg 悬在法兰外 0.24 m），而它们的增益恰恰是六个里最小的。
>
> 但把手腕增益调高（joint4 ×2.7、joint6 ×5）**反而更差**：最大误差从 0.10 涨到
> 0.30 rad，且 8 秒内不再稳定。**远端连杆惯量小，加大 Kp 会把固有频率推到 1 kHz
> 控制环撑不住的地方。**
>
> 而"5 倍增益变化几乎没改变系统性偏差"这一点本身就说明：它可能根本不是增益问题。
> 下一步该查的是——轨迹控制器在积分项还没拉到位时就因目标容差判定失败而停止驱动，
> 手臂于是停在放弃的那一刻。应该先放宽 `goal_time` 和目标容差，再动增益。

## 6. 容差为什么必须跟着控制方式一起改

`joint_trajectory_controller` 有三个容差，它们的含义**依赖于关节是怎么被驱动的**：

| 容差 | 含义 | 运动学关节 | 力矩关节 |
|---|---|---|---|
| `trajectory` | 路径跟踪偏差上限 | 无意义（永远为零），只能关掉 | 有意义，但要放宽——力矩驱动的关节按设计就会滞后 |
| `goal` | 终点偏差上限 | 可以很紧，但带载偏置会破坏它 | 反映真实定位精度 |
| `stopped_velocity_tolerance` | 终点速度上限 | 无意义，`SetPosition` 的速度不干净收敛 | 有意义，手臂确实会减速 |

> **在本项目里**：运动学版本把 `trajectory` 和 `stopped_velocity_tolerance` 都设为 0
> （关闭），`goal` 放到 0.05 rad。切到力矩控制时这三个都必须重设——把为刚性关节
> 打的补丁带到力矩控制里，会得到一堆互相矛盾的行为。

---

## 7. 延伸：阻抗控制

位置控制的目标是"不管外界如何，都要到达这个位置"，本质上是**刚性**的。当末端要与
环境接触时（本项目的接料围栏会碰到果串），我们更想要的是规定**接触时的力学行为**：

```
F = M_d·(ẍ_d − ẍ) + B_d·(ẋ_d − ẋ) + K_d·(x_d − x)
```

即让末端表现得像一个质量-弹簧-阻尼系统，`K_d` 小就"软"，大就"硬"。这就是阻抗控制。
它的前提是**能够精确控制关节力矩**——所以第 3 节的接口选择不是细节，而是能不能做
接触任务的分水岭。
